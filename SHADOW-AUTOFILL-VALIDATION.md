# Shadow mutation optimization: validation in progress

This change is related to [#21083](https://github.com/bitwarden/clients/pull/21083), which was closed without merging because its performance cost to autofill was uncertain, and [#21084](https://github.com/bitwarden/clients/pull/21084), which optimized cosmetic light-DOM mutations. It has not established that this alternative is safe or beneficial enough to merge.

The branch starts at `b65cd798e8564b14af50da5fa76b1d6acb268e33`, based on `105dc4facd4bdb1d63659b393125a43640108d8c`. On 2026-11-22, upstream `main` was `ad5a8f316667f875737c01ec77b6632ab4884430`; its collection service matched the branch parent. Additional lifecycle fixes and tests follow that commit.

In heuristic collection, a shadow mutation can skip a document collection when its affected roots and changed subtrees contain no potential fields or slots. Cached field visibility is still refreshed. Field-bearing roots, stylesheet changes, hosts with light children, targeting rules, and uncertain state take the broader path. Shadow observer options are unchanged; partial walks do not reconcile the hydration tracker's complete-scan state. A broad fallback invalidates heuristic caches before a manual collection can return stale results. The lifecycle fixes also reject visibility work from an earlier monitoring session and discard asynchronous visibility results for fields no longer in the cache.

The jsdom tests exercise field insertion, removal, movement, relabeling, a hidden input becoming fillable, late nested hydration, slots and stylesheets, explicit collection before the debounce, and a fieldless tooltip without a document collection. Additional tests use the real debounce with simulated timers for mixed mutations and a stop/restart, and verify that an in-flight visibility result cannot request overlay setup after restart. Visibility is mocked; these tests do not prove real browser visibility, overlay placement, or successful fill.

The four focused collection, DOM-query, hydration, and performance suites passed (389 tests), and the final shadow-mutation group passed separately (15 tests). `npm run test:types` passed, including strict mode. Repository-wide `npm run lint` passed with 367 warnings. Chrome and Firefox development builds completed with 88 and 1 webpack warnings respectively; these are build results, not browser test results.

No new performance comparison has been run. The original fixture and harness were not found in the checked local locations, the current browser-interactions-testing checkout, or the #21084 head tree. Its existing [benchmark documentation](https://github.com/bitwarden/browser-interactions-testing/blob/main/docs/performance.md) describes an instrumented extension and seeded vault setup. Earlier handoff figures are not independently reproducible and must not be attributed to this revision.

Remaining work includes an interleaved baseline-versus-change benchmark with distributions and scan/observer overhead, realistic field-bearing and nested-root controls, more lifecycle and coverage cases, and actual autofill and overlay validation in an unlocked extension with a dedicated test account. Chromium, Firefox, and Safari behavior has not been established by these jsdom tests. Maintainers must assess the evidence; no acceptance is implied.
